# Architecture Overview

この文書は、現在の業務ユースケースに沿った概念上の構成を示す。設計の正本は
[ユースケース知識バンドル](../product/application-use-cases/index.md) と
[ユビキタス言語](../product/ubiquitous-language/index.md) である。
具体的なモジュール名、保存形式、外部サービスの設定は技術リファレンスで扱う。

## 依存方向

```text
外部入口 -> 業務ユースケース -> 業務概念・境界契約
技術アダプタ -> 業務概念・境界契約
```

- 外部入口: チャネルからの入力、結果の通知、定期的な記憶整理の契機を受け取る。
- 業務ユースケース: メッセージの受付、応答作成、結果の通知、長期記憶の整理を担う。
- 業務概念・境界契約: 利用者、キャラクター、会話、会話履歴、応答結果、長期記憶、関係状態を表す。
- 技術アダプタ: 外部サービス、永続化、検索、ファイル形式などの差異を吸収する。

業務ユースケース同士は呼び出さない。複数の業務ユースケースから再利用する処理は、
共有する業務責務または技術アダプタへ切り出す。

Discord公開議論は1対1会話core domainとは別のBounded Contextであり、
[Discord公開議論バンドル](../product/discussion/index.md)に業務上の境界を定義する。

## 実行上の責務

- チャネル入口は、外部メッセージを会話メッセージへ変換し、会話の結果を元のチャネルへ返す。
- 会話の受付、応答作成、結果の通知は、一つの要求に対する論理的な流れとして完了する。
- 記憶整理の入口は、定期的な契機から長期記憶の整理を開始する。
- 永続化や検索は、業務ユースケースから見える境界契約の実装として扱う。

会話処理は、次の論理順に完了する。

```text
メッセージを受け付ける
  -> 会話への応答を作成する
  -> 応答結果を利用者へ届ける
```

失敗した処理は、未完了のまま成功として扱わない。業務ユースケースとは独立した永続的な
再処理や障害回復の仕組みは、この構成の前提にしない。

## 会話フロー

1. チャネルが外部メッセージをシステムへ渡す。
2. システムがチャネル上の利用者識別子を利用者へ結び付ける。結び付けられない場合は受付を失敗させる。
3. システムが利用者のメッセージを会話履歴へ記録し、受付済みメッセージとする。
4. システムが更新前の関係状態から関係行動コンテキストを選び、会話履歴、長期記憶、必要な外部情報とともに応答を作成する。
5. システムが応答作成と並行して今回の会話を暫定関係シグナルとして評価し、成功した評価を次回応答用に保存する。
6. システムが応答結果を元のチャネルへ届け、届けた内容を会話履歴へ反映する。
7. どの段階でも失敗は失敗結果として確定し、未完了の処理を成功として扱わない。ただし暫定関係評価の失敗は生成済み応答を失敗させない。

同じ外部メッセージを複数の受付対象として扱わない。
チャネル上の識別子は、利用者と会話を特定するための情報として扱い、業務上の利用者と混同しない。

## 長期記憶

会話履歴は利用者と対話相手の双方のメッセージを保持する。記憶整理は未評価の会話を
定期的に読み取り、次の3種類を更新する。

- 人物像: 利用者・対話相手の安定した属性。
- 出来事: 期間内の経験をまとめた記憶。
- 対象・関係: 正規化された対象と、その関係。

記憶整理では、毎回新しい記憶を増やすのではなく、将来の対話に有用な内容だけを残す。
各記憶には根拠と不確実性を関連付け、判断できない内容は保留する。
検索用の派生情報は長期記憶から作られるものであり、業務上の正本とは扱わない。

## 関係状態

関係状態はキャラクターと利用者の組ごとにSQLへ保存し、長期記憶やMarkdown Entityへ混入させない。
応答時には保存済み好感度から共通関係段階を解決し、キャラクター定義にある候補からアプリケーションが
一つの関係行動コンテキストを選ぶ。AIはシグナル評価を担うが、段階解決や行動選択を担わない。

日次の会話履歴整理は長期記憶更新案と確定関係シグナルを一度に抽出し、暫定イベントの置換、全有効イベントの
再計算と処理済み記録を同じDBトランザクション境界で確定する。技術詳細は
[Relationship System](../infrastructure/relationship-system.md)を参照する。

## 業務ユースケースと境界

| 業務ユースケース | 主な責務 |
| --- | --- |
| メッセージを受け付ける | 利用者と会話を特定し、会話履歴へ記録する |
| 会話への応答を作成する | 更新前の関係状態から追加コンテキストを選び、会話履歴、長期記憶、必要な外部情報から応答を作る |
| 応答結果を利用者へ届ける | 応答結果を元の会話へ届け、結果を記録する |
| 会話履歴を整理する | 会話から長期記憶と確定関係シグナルを抽出し、根拠とともに確定する |

外部チャネル、外部情報源、永続化、ファイル形式は業務ユースケースから直接参照しない。

## 対象外

組織・team・membership管理、管理API、グループ会話、メディア入力、自発的通知、
配送保証、障害回復、永続的な処理待ちはこのアプリケーションの対象外である。
