# アクター別ハイレベルユースケースとユースケース記述

## 1. 文書の目的

本書は、agentic-chat-foundation が提供すべき能力を、アクターの目的から定義する。
既存のクラス、処理名、データ構造、実行環境は能力を発見するための材料としてのみ扱い、
目標設計の前提にしない。

ユースケースは、アクターにとって意味のある結果を生む業務フローとして記述する。
内部状態、メッセージ配送方式、再試行方式、保存形式などは本書の対象外とする。

ステータス: **目標能力の定義**

## 2. プロジェクトの目的

利用者が1対1のテキスト会話を通じて、役割や人格を持つ対話相手と継続的に対話できることを目的とする。

システムは、現在の会話、過去の交流から整理された長期記憶、必要に応じて取得した外部情報を用いて
応答を作成する。会話履歴はそのままの記録として保持し、長期記憶は将来の対話に有用な意味だけを
周期的に整理する。

## 3. スコープ

### 3.1 対象

- 外部の会話チャネルを通じた1対1のテキスト会話
- 利用者のメッセージの受信、記録、応答、結果の通知
- 応答に必要な外部情報の一時的な取得
- 会話履歴を用いた文脈の継続
- 人物像、エピソード、対象・関係の長期記憶の生成・更新・参照
- 応答処理や長期記憶整理の失敗を、失敗結果として確定すること

### 3.2 対象外

- 組織、チーム、メンバーシップの管理
- 対話目的とは独立した利用者・組織管理機能
- グループ会話、ルーム会話、複数利用者間の調整
- 画像、スタンプ、音声などの非テキスト入力
- 利用者から開始されない自発的な通知や外部操作
- 自動retry、未完了処理の回復、永続的な処理待ち
- 特定のAIモデル、データベース、キュー、ファイル形式、プロセス構成

## 4. アクター

### 4.1 主要アクター

#### 利用者

会話チャネルを通じてシステムへメッセージを送り、応答を受け取る人。
チャネル上の識別子と、業務上の利用者の同一性は別の概念として扱う。

#### システム

メッセージを受け付け、会話文脈を組み立て、応答を作成し、長期記憶を整理する対話システム。
利用者の操作を直接の起点としない周期処理も、システムの業務として扱う。

### 4.2 補助アクター

#### 会話チャネル

利用者のメッセージをシステムへ渡し、システムの結果を利用者へ届ける外部サービス。

#### 外部情報源

システムからの問い合わせに対し、システム内にない情報や現在性のある情報を返す外部サービス。

#### 時間

長期記憶の整理を開始する時間経過または定期的な契機。

## 5. ハイレベルユースケース

各項目は、アクターに必要な能力を1行で表す。

### 5.1 利用者

| ID | ハイレベルユースケース |
|---|---|
| HL-U01 | 利用者は、会話チャネルからシステムへメッセージを送信できる。 |
| HL-U02 | 利用者は、現在の会話に沿った応答を受け取ることができる。 |
| HL-U03 | 利用者は、過去の交流を反映した継続的な対話ができる。 |
| HL-U04 | 利用者は、応答できない場合に、その結果を認識できる。 |

### 5.2 システム

| ID | ハイレベルユースケース |
|---|---|
| HL-S01 | システムは、利用者からのメッセージを受信し、会話履歴として記録できる。 |
| HL-S02 | システムは、メッセージを正しい利用者と会話に関連付け、応答対象にできる。 |
| HL-S03 | システムは、現在の会話と関連する長期記憶を使って応答を作成できる。 |
| HL-S04 | システムは、必要な場合に外部情報を取得し、応答へ反映できる。 |
| HL-S05 | システムは、生成した応答または応答不能の結果を元の会話へ届けられる。 |
| HL-S06 | システムは、会話から人物像、エピソード、対象・関係の長期記憶を生成・更新できる。 |
| HL-S07 | システムは、利用者ごとの会話履歴と長期記憶を分離して扱える。 |

## 6. 業務ユースケースへの集約

ハイレベルユースケースは、次の4つの業務ユースケースで実現する。

| ID | 業務ユースケース | 実現するハイレベルユースケース |
|---|---|---|
| UC-01 | メッセージを受け付ける | HL-U01、HL-S01、HL-S02、HL-S07 |
| UC-02 | 会話への応答を作成する | HL-U02、HL-U03、HL-S03、HL-S04、HL-S07 |
| UC-03 | 応答結果を利用者へ届ける | HL-U02、HL-U04、HL-S05 |
| UC-04 | 会話から長期記憶を整理する | HL-U03、HL-S06、HL-S07 |

### 6.1 粒度の判断

- チャネルごとの受信は、UC-01の入口の違いとして扱う。
- 会話履歴の参照、長期記憶の参照、外部情報の取得は、UC-02内の判断・補助フローとする。
- 応答の文面を作る処理と、必要な補助情報を集める処理を別の利用者向けユースケースに分けない。
- 応答不能は独立したユースケースにせず、UC-02またはUC-03の例外結果とする。
- 長期記憶の整理は、利用者の応答とは異なる時間起点を持つため、UC-04として分ける。
- 自動retry、処理待ち、復旧、派生データの再構築は業務ユースケースとして定義しない。

## 7. ユースケース記述

### UC-01 メッセージを受け付ける

#### 目的

利用者が送信したメッセージを、正しい会話へ一度だけ受け付け、応答作成の対象にする。

#### 主要アクター

利用者

#### 補助アクター

会話チャネル

#### 起点

利用者が、対応する会話チャネルからテキストメッセージを送信する。

#### 事前条件

- 利用者がシステムとの1対1の会話を開始または継続できる。
- 会話チャネルが、送信元とメッセージを識別できる情報を提供する。

#### 基本フロー

1. 利用者が会話チャネルへメッセージを送信する。
2. 会話チャネルがメッセージをシステムへ渡す。
3. システムが、対応する会話と受け付け可能な入力であることを確認する。
4. システムが、メッセージを利用者と会話へ関連付ける。
5. システムが、受信内容を変更せず会話履歴へ記録する。
6. システムが、応答作成の対象としてメッセージを受け付ける。
7. システムが、会話チャネルへ受付結果を返す。

#### 代替・例外フロー

##### A1. 同じメッセージが通常処理中に再送された

1. システムが、同じメッセージに対する応答対象を増やさない。
2. 既存の受付結果を有効とする。

##### A2. 対応していない入力だった

1. システムが、メッセージを応答作成の対象として受け付けない。
2. 通知可能な場合は、対応できないことを利用者へ示す。

##### A3. 受付を確定できなかった

1. システムが、メッセージを受け付け済みとして扱わない。
2. 自動的な再処理は行わず、受付失敗として扱う。

#### 成功時の事後条件

- メッセージが一つの会話履歴へ記録されている。
- メッセージが一つの応答作成対象として確定している。
- 利用者と会話の関連付けが確定している。

#### 最低保証

受付が確定していないメッセージから、応答作成は開始されない。

#### 関連ハイレベルユースケース

HL-U01、HL-S01、HL-S02、HL-S07

### UC-02 会話への応答を作成する

#### 目的

受け付けたメッセージに対して、対話相手の役割と会話文脈に沿った一つの論理的な応答を作成する。

#### 主要アクター

システム

#### 起点

UC-01で受け付けたメッセージが、応答作成の対象になる。

#### 事前条件

- 対象メッセージが受付済みである。
- 対象メッセージ以前の会話履歴を参照できる。
- 対話相手の役割と応答上の制約を確認できる。

#### 基本フロー

1. システムが、今回応答する利用者メッセージを確認する。
2. システムが、今回のメッセージ以前の直近会話を確認する。
3. システムが、現在の利用者に属する関連長期記憶を確認する。
4. システムが、対話相手の役割、利用者の意図、会話文脈を解釈する。
5. システムが、外部情報の不足があるか判断する。
6. 不足がある場合、許可された外部情報源から必要な情報を取得する。
7. システムが、利用可能な会話履歴、長期記憶、外部情報を用いて応答を作成する。
8. システムが、応答が役割と制約を満たすことを確認する。
9. システムが、応答結果をUC-03へ渡す。

#### 代替・例外フロー

##### A1. 関連する長期記憶がなかった

1. システムが、直近会話と今回のメッセージだけで応答を作成する。
2. 記憶がない内容を事実として補完しない。

##### A2. 外部情報を取得できなかった

1. システムが、取得できなかった情報を推測で補わない。
2. 利用可能な情報だけで回答できる場合は、制約を明示した応答を作成する。
3. 回答できない場合は、応答不能の結果を作成する。

##### A3. 応答を作成できなかった

1. システムが、不完全な内容を通常の応答として確定しない。
2. システムが、応答不能の結果を作成する。
3. 自動retryや後続の回復処理は行わない。

##### A4. 応答作成中に後続メッセージが届いた

1. システムが、後続メッセージを今回の文脈へ混入させない。
2. 後続メッセージを、今回の結果が確定した後の別の応答対象とする。

#### 成功時の事後条件

- 対象メッセージに対する一つの論理的な応答結果が作成されている。
- 応答が、今回のメッセージより後の会話を参照していない。
- 応答に利用した長期記憶と外部情報が、今回の応答に関連付けられている。

#### 最低保証

検証されていない情報や生成途中の内容は、確定した応答として扱われない。

#### 関連ハイレベルユースケース

HL-U02、HL-U03、HL-S03、HL-S04、HL-S07

### UC-03 応答結果を利用者へ届ける

#### 目的

確定した応答または応答不能の結果を、元の会話の利用者へ届ける。

#### 主要アクター

システム

#### 補助アクター

会話チャネル

#### 起点

UC-02で応答結果または応答不能の結果が確定する。

#### 事前条件

- 対象利用者と元の会話が特定されている。
- 利用者へ提示する内容が確定している。

#### 基本フロー

1. システムが、受付時に確定した会話を配送先とする。
2. システムが、結果を会話チャネルで提示可能な形に整える。
3. システムが、結果を会話チャネルへ渡す。
4. 会話チャネルが、結果を利用者へ届ける。
5. システムが、提示した内容と結果を会話履歴へ記録する。

#### 代替・例外フロー

##### A1. 会話チャネルへ届けられなかった

1. システムが、送達不能の結果として処理を終了する。
2. 自動再送や別チャネルへの切り替えは行わない。

##### A2. 応答不能の結果だった

1. システムが、応答できなかった理由を利用者へ提示可能な範囲で示す。
2. 応答不能の結果を会話履歴へ記録する。

#### 成功時の事後条件

- 利用者が応答または応答不能の結果を受け取っている。
- 結果が会話履歴へ反映されている。

#### 最低保証

送達を確認できない結果を、送達済みとして扱わない。

#### 関連ハイレベルユースケース

HL-U02、HL-U04、HL-S05

### UC-04 会話から長期記憶を整理する

#### 目的

蓄積した会話から将来の対話に有用な内容を抽出し、根拠と不確実性を保った長期記憶として整理する。

#### 主要アクター

システム

#### 補助アクター

時間

#### 起点

所定の時間が経過するか、未整理の会話が整理条件を満たす。

#### 事前条件

- 対象利用者の会話履歴が存在する。
- 対象範囲と会話の所有者を特定できる。
- 既存の長期記憶を比較対象として参照できる。

#### 基本フロー

1. システムが、一人の利用者に属する会話範囲を選ぶ。
2. システムが、将来の対話に有用な会話と、記憶に不要な会話を区別する。
3. システムが、有用な会話から次の記憶候補を抽出する。
   1. 安定した特徴、嗜好、長期的な制約を表す人物像。
   2. 出来事、経緯、結果、反応を表すエピソード。
   3. 人物、物事、計画、その属性や関係を表す対象・関係。
4. システムが、候補へ根拠となる会話、不確実性、観測時点を関連付ける。
5. システムが、既存の記憶と比較し、新規作成、更新、統合、変更なしを判断する。
6. システムが、利用者境界、根拠、重複、矛盾を確認する。
7. システムが、確認済みの記憶整理結果を確定する。

#### 代替・例外フロー

##### A1. 長期記憶に値する内容がなかった

1. システムが記憶を生成しない。
2. 対象会話を評価済みとして扱う。

##### A2. 既存の記憶と重複した

1. システムが同じ内容の記憶を増やさない。
2. 新しい根拠や観測時点が有用な場合だけ既存記憶を更新する。

##### A3. 既存の記憶と矛盾した

1. システムが、状態や嗜好の時間的変化として扱えるか確認する。
2. 変化として扱える場合は、以前の状態を消さずに変化を記録する。
3. 判断できない場合は、不確実または未解決の状態で保持する。

##### A4. 根拠または所有者を確認できなかった

1. システムが、その候補を長期記憶として確定しない。
2. 対象会話を整理完了とはせず、次回以降に再評価可能な状態とする。

##### A5. 記憶整理に失敗した

1. システムが、その回の整理を失敗として終了する。
2. 自動retryや回復処理は行わない。

#### 成功時の事後条件

- 有用な人物像、エピソード、対象・関係の記憶が生成または更新されている。
- 各記憶から根拠となる会話と不確実性を追跡できる。
- 同じ会話範囲を次回評価しても、同じ記憶が重複して増えない。
- 元の会話履歴は、長期記憶とは別の根拠として保持されている。

#### 最低保証

別の利用者の会話や記憶は参照・変更されず、根拠を確認できない候補は確定されない。

#### 関連ハイレベルユースケース

HL-U03、HL-S06、HL-S07

## 8. 共通業務規則

| ID | 業務規則 |
|---|---|
| BR-01 | 一つのメッセージは、利用者と一つの会話へ関連付けられる。 |
| BR-02 | 正常処理では、一つの利用者メッセージから一つの論理的な応答結果を作る。 |
| BR-03 | 同じ会話のメッセージは論理的な順序で扱い、後続メッセージを先行処理の文脈へ混入させない。 |
| BR-04 | 応答の宛先は受付時の会話で決まり、応答作成側が任意に選ばない。 |
| BR-05 | 外部情報は現在の応答の一時的な根拠であり、長期記憶へ自動的に昇格しない。 |
| BR-06 | 会話履歴は変更していない記録、長期記憶は意味を抽出した整理結果として扱う。 |
| BR-07 | 人物像は安定した特徴、エピソードは時間を伴う出来事、対象・関係は人物や物事の状態を表す。 |
| BR-08 | 会話履歴、長期記憶、参照結果は利用者の境界を越えない。 |
| BR-09 | 不確実な記憶は事実として補完せず、根拠と不確実性を保持する。 |
| BR-10 | 失敗した処理はその場で失敗として確定し、自動retryや自動回復を行わない。 |

## 9. 完了状態

### 応答完了

応答結果が利用者へ届けられ、会話履歴へ反映されている。

### 応答不能

応答を作成または送達できないことが確定し、可能な範囲で利用者へ示され、会話履歴へ記録されている。

### 記憶整理完了

対象会話の評価と、生成・更新すべき長期記憶の確定が完了している。

### 記憶整理失敗

対象会話の記憶整理を確定できず、その回の処理が失敗として終了している。

## 10. 将来判断する事項

本書では決めず、必要になった時点で別途要件化する。

- 利用者が長期記憶を閲覧、訂正、削除できるか。
- 会話履歴と長期記憶をどの期間保持するか。
- 複数チャネル上の同じ人物を一人の利用者として統合するか。
- 応答不能時に別の通知方法を提供するか。
- グループ会話、メディア入力、自発的な通知を対象にするか。
- 対話相手の役割や人格を誰が設定・変更するか。
