# 目的

受け付けたメッセージに対して、キャラクターの人格、会話文脈、応答作成開始時点の関係状態に沿った
一つの論理的な応答を作成する。今回の会話から得る関係シグナルは次回応答以降へ反映する。

# アクター

## 主要アクター

システム

# 起点

[メッセージを受け付ける](/use-cases/accept-incoming-message.md) で受け付けたメッセージが、
応答作成の対象になる。

# 事前条件

- 対象メッセージが受付済みである。
- 対象メッセージ以前の会話履歴を参照できる。
- 対話相手の役割と応答上の制約を確認できる。
- 対象メッセージのキャラクターと利用者を特定できる。
- キャラクターと利用者の組に対応する関係状態を参照できる。未作成なら初期状態として扱える。

# 基本フロー

1. システムが、今回応答する利用者メッセージを確認する。
2. システムが、対象キャラクターに属する今回のメッセージ以前の直近会話を確認する。
3. システムが、現在の利用者に属する関連長期記憶を確認する。
4. システムが、キャラクターと利用者の更新前の関係状態から共通関係段階を解決する。
5. システムが、関係段階に対応するキャラクター固有候補から、今回の関係行動コンテキストを再現可能な方法で一つ選ぶ。
6. システムが、人格、安全制約、選択済み関係行動コンテキスト、利用者の意図、会話文脈を応答用コンテキストとして組み立てる。
7. システムが、外部情報の不足があるか判断する。
8. 不足がある場合、許可された外部情報源から必要な情報を取得する。
9. システムが、利用可能なコンテキストを用いて応答を作成する。同じ応答処理で外部機能へ再入場しても関係行動コンテキストを変えない。
10. 応答作成と並行して、システムが今回の利用者メッセージから関係シグナル候補を評価する。
11. 即時評価に成功した場合、基準を満たす非中立シグナルを暫定シグナルとして独立して保存する。
12. システムが、応答が人格と制約を満たすことを確認する。
13. システムが、応答結果を[応答結果を利用者へ届ける](/use-cases/deliver-conversation-result.md)へ渡す。

# 代替・例外フロー

## A1. 関連する長期記憶がなかった

1. システムが、直近会話と今回のメッセージだけで応答を作成する。
2. 記憶がない内容を事実として補完しない。

## A2. 外部情報を取得できなかった

1. システムが、取得できなかった情報を推測で補わない。
2. システムが、応答不能の結果を作成する。

## A3. 応答を作成できなかった

1. システムが、不完全な内容を通常の応答として確定しない。
2. システムが、応答不能の結果を作成する。
3. システムが、未確定の内容を通常の応答として扱わない。

## A4. 応答作成中に後続メッセージが届いた

1. システムが、後続メッセージを今回の文脈へ混入させない。
2. 後続メッセージを、今回の結果が確定した後の別の応答対象とする。

## A5. 関係状態がまだ存在しなかった

1. システムが、好感度 `0` の初期関係状態として関係段階を解決する。
2. 初期状態がないことを理由に応答を失敗させない。

## A6. 即時関係シグナルを評価または保存できなかった

1. システムが、生成済みの応答を失敗させない。
2. 暫定シグナルを保存せず、日次の[会話履歴を整理する](consolidate-conversation-history.md)で再評価可能にする。

## A7. 関係状態を読み取れなかった

1. システムが、推測した関係状態で応答を作成しない。
2. システムが、応答不能の結果を作成する。

# 成功時の事後条件

- 対象メッセージに対する一つの論理的な応答結果が作成されている。
- 応答が、今回のメッセージより後の会話を参照していない。
- 応答に利用した長期記憶と外部情報は、その応答の根拠として扱われる。
- 応答に使った関係行動コンテキストは更新前の関係状態から選ばれている。
- 今回保存された暫定シグナルは現在の応答へ遡って反映されず、次回応答から利用可能である。
- 関係段階、好感度の数値、未選択の候補は応答生成コンテキストへ公開されていない。

# 最低保証

検証されていない情報や生成途中の内容は確定した応答として扱われず、関係評価の失敗は関係状態を推測で変更しない。
